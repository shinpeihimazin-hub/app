# rental-watch — 賃貸物件 監視

条件に合う物件が出た瞬間に気づくための監視。**探すためではなく、待ち伏せるための道具。**

在庫が極端に少ない条件（2026-07-28 時点で全ヒット1件）なので、
「探す」より「出た瞬間に取る」方が勝率が高い、という判断に基づく。

## 使い方

```bash
python3 rental-watch/watch.py --new      # 新着だけ見る（定期実行はこちら／実測172秒）
python3 rental-watch/watch.py            # 全件走査（週次の検算用／実測15〜20分）
python3 rental-watch/watch.py --dry-run  # 何も書かない
python3 rental-watch/watch.py --all      # 既知も含めて全ヒットを表示
python3 rental-watch/watch.py --speed    # 掲載速度の集計だけ出す（取得しない）
```

## 定期実行

| Routine | 間隔 | 内容 |
|---|---|---|
| 賃貸物件 監視（1時間ごと・新着のみ） | 毎時 | `--new`。約3分で終わる |
| 賃貸物件 週次フルスキャン | 日曜 21:00 JST | `--new` なし。新着モードの取りこぼしを検算 |

## なぜ新着モードなのか（2026-07-31）

**条件に合う部屋は掲載された瞬間に埋まる。** 実際、久が原5もパシフィックコート中延も
こちらが見つけた時点では掲載が生きていたが、問い合わせたら埋まっていた。
9サイト・のべ8,000件を走査しても、出てくるのは「もう埋まっている物件」ばかりだった。

だから全在庫を数え直すことに意味がない。必要なのは「この1時間で新しく出たもの」だけ。

さらに実務上の問題として、駅を8→28に増やし SUUMO・HOME'S・エイブルを足した結果、
全件走査が10分以上かかるようになり、**定期実行が完走しなくなっていた**
（2026-07-30 17:12 を最後に実行記録が丸一日途絶えた）。

新着モードでの実測:

| ソース | 全件 | 新着モード | やったこと |
|---|---|---|---|
| 不動産ジャパン | 5分以上 | 26秒 | 一覧に構造・敷礼・管理費が載っていたので詳細取得をやめた |
| ハトマークサイト | 136秒 | 57秒 | `sort1=ASRT11`（更新日 新しい順）＋2ページ |
| HOME'S | 203秒 | 20秒 | 28駅 → 5区（世田谷区も入り、逆に範囲が広がった） |
| SUUMO | 20秒 | 21秒 | `po1=09`（新着順）＋4ページ |
| エイブル | 22秒 | 20秒 | `jks=3`（3日以内の新着） |
| at home | 41秒 | 43秒 | 変更なし |
| **合計** | **10分以上** | **172秒** | |

## 却下した物件（rejected.json）

本人が見て落とした物件は `rejected.json` に fingerprint と理由を入れて除外する。
条件は満たしているので seen.json だけでは止まらず、掲載も生きたままなので
入れないと毎時同じものが飛ぶ（実測で初回通知4件が全部これだった）。

終了コード: `0` 新着なし / `1` 新着あり / `2` 取得エラー

## 監視対象

**カナリーは使わない。**本人が自分で見ているため重複する。

- **不動産ジャパン**（公益財団法人 不動産流通推進センター）— 対象8駅で直接検索
- **ハトマークサイト**（全国宅地建物取引業協会連合会）— 品川/大田/目黒/港 → 8駅で絞込
- **at home** — 対象8駅の駅ページ
- **SUUMO** — 品川/大田/目黒/港。敷礼ゼロの実測件数が他サイトと桁違いだったため追加した
- **LIFULL HOME'S** — 対象28駅。構造（RC/SRC）をサーバ側で絞れて、母数も最大
- **エイブル** — 品川/大田/目黒/港。**一覧に建物構造が出る**ので RC 判定を人手に回さずに済む

**ハウスコムは未対応。**検索が `/search/` へのセッション付きPOSTで、
再現しようとすると404が返る。在庫はATBB由来で上記6サイトと重なるため優先度は低い。

**いい部屋ネットは条件がURLに乗らない**（`serializedCondition` が全部 null で返る）。
物件データ自体は `__NEXT_DATA__` に入っているので、区単位で全件取って
こちらで絞る形なら取得できる。連続アクセスで403に入るため間隔を空ける必要がある。

条件の詳細と、実測したパラメータの意味は [`conditions.md`](conditions.md) にある。

## 設計上の判断

**「新着ゼロ」と「取得失敗」を区別する。**
サイト構造が変わってスクレイプが壊れると、黙って「新着なし」を返し続けて
監視しているつもりで何も見ていない状態になる。これを避けるため、
結果ページに期待する目印が無ければ**エラー（終了コード2）として報告する**。

**走ったこと自体を記録に残す（`runlog.md`）。**
新着ゼロの回は通知を出さない設計なので、外から見ると「正常に静か」と
「壊れて無音」が区別できない。毎回1行追記することで、
**3時間おきに行が増えていなければ止まっている**と即断できるようにした。

**記録の永続化はスクリプト自身が行う。**
コンテナは揮発するのでコミットしないと記録が消えるが、これを定期実行の
プロンプト文言に任せると、文言の書き換えや解釈のブレで簡単に壊れる。
そこで `watch.py` が実行の最後に `runlog.md` と `seen.json` を自分で
コミット＆プッシュする。差分が無ければ何もしない。git が失敗しても
監視自体は成功扱いにする（記録の欠落で監視を落とす方が損）。
ローカルで検証するときは `--no-commit` を付ける。

**物件をサイト跨ぎで同一判定する（fingerprint）。**
`賃料 + 専有面積 + 正規化した住所` をキーにする。住所は全角/半角・「東京都」の
有無・建物名の付き方がサイトごとに違うので正規化してから突き合わせる。
これで同じ部屋を重複通知しないだけでなく、**どのサイトに何時間早く出たか**が
`seen.json` の `sources` に溜まる。`--speed` でその集計を出せる。

## 掲載速度の実測について

「どのポータルが最速か」はネット上に主張が多いが、出典がほぼ不動産仲介業者の
ブログ（＝自社送客の動機がある側）で、独立した検証が見当たらない。
だから**主張を採用せず、自分のデータで測る**方針にした。
同じ部屋が2サイト以上で観測されるまで蓄積が要るので、答えが出るには数週間かかる。

なお制度上、**レインズ登録義務は専属専任5営業日・専任7営業日以内、一般媒介は義務なし**。
つまりポータルに出る前に最大1週間の空白があり、その間は元付け業者しか知らない。
**ポータル間の速度差より、元付けへの条件登録の方が構造的に速い。**

**「家賃17万」は管理費・共益費込みで確定している**（`RENT_CAP_INCLUSIVE = True`）。
各サイトへのクエリは賃料（管理費抜き）17万以下で投げる。管理費は必ず0以上なので
「賃料 ≤ 17万」は「込み ≤ 17万」の上位集合になり、取りこぼしは出ない。
込みで超過するものは取得後にこちら側で落とす。

## 自動で判定できないもの

通知が来たら、この2つは自分で確認すること。

1. **各室の畳数**（リビング6畳以上・寝室4畳以上）— 両サイトにフィルタが無い。間取り図で見る
2. **二人入居可** — 検索段階で絞ると母数が激減するため外している。問い合わせ時に必ず聞く

## 条件を変えるとき

`watch.py` 冒頭の定数を書き換える。

| 定数 | 意味 |
|---|---|
| `RENT_CAP` | 賃料上限（円） |
| `RENT_CAP_INCLUSIVE` | `True` で管理費込み判定 |
| `AREA_MIN` | 専有面積の下限（㎡） |
| `AGE_MAX` | 築年数の上限（年） |
| `WALK_MAX` | 駅徒歩の上限（分） |
| `TARGET_STATIONS` | 対象駅。増やすときは `FDJ_STATION_CODES` と `HOMES_STATIONS` も足すこと |
| `ABLE_QUERY` | エイブルの絞り込み（`sf`面積 `h`築年 `j`徒歩 `m`間取り）。家賃はサーバ側で効かない |

駅を増やす場合、不動産ジャパンの駅コードは
`https://www.fudousan.or.jp/property/rent/13/station?ptm[]=0303` の
`name="wst[]" value=...` から取れる。

## 併用すべきもの（このbotが落ちても効く保険）

- 不動産ジャパン / ハトマークサイトの新着メール登録
- 元付け・管理会社への条件登録（募集前の情報はWebに出ない）
  - ランドワーク不動産（五反田・大崎／自社グループ所有物件あり）
  - 品川目黒不動産管理（不動前・西五反田・下目黒が重点の管理会社）
  - カドヤ不動産 / 蒲田大森不動産ネクスチャー（大森側）
