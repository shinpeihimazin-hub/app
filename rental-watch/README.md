# rental-watch — 賃貸物件 監視

条件に合う物件が出た瞬間に気づくための監視。**探すためではなく、待ち伏せるための道具。**

在庫が極端に少ない条件（2026-07-28 時点で全ヒット1件）なので、
「探す」より「出た瞬間に取る」方が勝率が高い、という判断に基づく。

## 使い方

```bash
python3 rental-watch/watch.py            # 差分を報告し seen.json / runlog.md を更新
python3 rental-watch/watch.py --dry-run  # 何も書かない
python3 rental-watch/watch.py --all      # 既知も含めて全ヒットを表示
python3 rental-watch/watch.py --speed    # 掲載速度の集計だけ出す（取得しない）
```

終了コード: `0` 新着なし / `1` 新着あり / `2` 取得エラー

## 監視対象

**SUUMO / LIFULL HOME'S / カナリー は使わない。**本人が自分で見ているため重複する。

- **不動産ジャパン**（公益財団法人 不動産流通推進センター）— 対象8駅で直接検索
- **ハトマークサイト**（全国宅地建物取引業協会連合会）— 品川/大田/目黒/港 → 8駅で絞込
- **at home** — 対象8駅の駅ページ

条件の詳細と、実測したパラメータの意味は [`conditions.md`](conditions.md) にある。

## 設計上の判断

**「新着ゼロ」と「取得失敗」を区別する。**
サイト構造が変わってスクレイプが壊れると、黙って「新着なし」を返し続けて
監視しているつもりで何も見ていない状態になる。これを避けるため、
結果ページに期待する目印が無ければ**エラー（終了コード2）として報告する**。

**走ったこと自体を記録に残す（`runlog.md`）。**
新着ゼロの回は通知を出さない設計なので、外から見ると「正常に静か」と
「壊れて無音」が区別できない。毎回1行追記することで、
**3時間おきに行が増えていなければ止まっている**と即断できるようにした。

**記録の永続化はスクリプト自身が行う。**
コンテナは揮発するのでコミットしないと記録が消えるが、これを定期実行の
プロンプト文言に任せると、文言の書き換えや解釈のブレで簡単に壊れる。
そこで `watch.py` が実行の最後に `runlog.md` と `seen.json` を自分で
コミット＆プッシュする。差分が無ければ何もしない。git が失敗しても
監視自体は成功扱いにする（記録の欠落で監視を落とす方が損）。
ローカルで検証するときは `--no-commit` を付ける。

**物件をサイト跨ぎで同一判定する（fingerprint）。**
`賃料 + 専有面積 + 正規化した住所` をキーにする。住所は全角/半角・「東京都」の
有無・建物名の付き方がサイトごとに違うので正規化してから突き合わせる。
これで同じ部屋を重複通知しないだけでなく、**どのサイトに何時間早く出たか**が
`seen.json` の `sources` に溜まる。`--speed` でその集計を出せる。

## 掲載速度の実測について

「どのポータルが最速か」はネット上に主張が多いが、出典がほぼ不動産仲介業者の
ブログ（＝自社送客の動機がある側）で、独立した検証が見当たらない。
だから**主張を採用せず、自分のデータで測る**方針にした。
同じ部屋が2サイト以上で観測されるまで蓄積が要るので、答えが出るには数週間かかる。

なお制度上、**レインズ登録義務は専属専任5営業日・専任7営業日以内、一般媒介は義務なし**。
つまりポータルに出る前に最大1週間の空白があり、その間は元付け業者しか知らない。
**ポータル間の速度差より、元付けへの条件登録の方が構造的に速い。**

**「家賃17万」は込み/抜きが未確定なので、広い方（賃料17万以下）で取得する。**
通知には管理費込みの金額を併記し、込みで17万を超えるものには警告を付ける。
込みで確定したら `watch.py` の `RENT_CAP_INCLUSIVE` を `True` にする。

## 自動で判定できないもの

通知が来たら、この2つは自分で確認すること。

1. **各室の畳数**（リビング6畳以上・寝室4畳以上）— 両サイトにフィルタが無い。間取り図で見る
2. **二人入居可** — 検索段階で絞ると母数が激減するため外している。問い合わせ時に必ず聞く

## 条件を変えるとき

`watch.py` 冒頭の定数を書き換える。

| 定数 | 意味 |
|---|---|
| `RENT_CAP` | 賃料上限（円） |
| `RENT_CAP_INCLUSIVE` | `True` で管理費込み判定 |
| `AREA_MIN` | 専有面積の下限（㎡） |
| `AGE_MAX` | 築年数の上限（年） |
| `WALK_MAX` | 駅徒歩の上限（分） |
| `TARGET_STATIONS` | 対象駅。増やすときは `FDJ_STATION_CODES` も足すこと |

駅を増やす場合、不動産ジャパンの駅コードは
`https://www.fudousan.or.jp/property/rent/13/station?ptm[]=0303` の
`name="wst[]" value=...` から取れる。

## 併用すべきもの（このbotが落ちても効く保険）

- 不動産ジャパン / ハトマークサイトの新着メール登録
- 元付け・管理会社への条件登録（募集前の情報はWebに出ない）
  - ランドワーク不動産（五反田・大崎／自社グループ所有物件あり）
  - 品川目黒不動産管理（不動前・西五反田・下目黒が重点の管理会社）
  - カドヤ不動産 / 蒲田大森不動産ネクスチャー（大森側）
