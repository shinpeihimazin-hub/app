## 専有面積の下限 — クエリは35で投げて37はこちらで判定する

各サイトの面積フィルタは**5㎡刻みしか受け付けない**（35の次が40で、37という選択肢が無い）。
37をそのまま投げると無効値になって絞り込みが外れるので、
`AREA_QUERY_MIN`（= 5の倍数に切り下げた値 = 35）でクエリを投げ、
37の判定はスクリプト側で行う。切り下げた側は上位集合なので取りこぼしは出ない。

対象: SUUMO `mb` / HOME'S `cond[housearea]` / エイブル `sf` /
ハトマーク `building_area_all_from` / 不動産ジャパン `exclusive_area_from`

## 初期費用は「同じ部屋でも掲載業者ごとに違う」（2026-08-01 実測）

**watch.py はこれをまだ見ていない。既知の取りこぼし。**

SUUMOの物件ページには、同じ部屋を扱う他店舗の掲載IDが埋め込まれている:

```html
<form id="sonota_tenpo_form" action="/jj/chintai/common/FR301FK030/">
  <input name="bc" value="100519072730"/>   ← この掲載にだけフリーレント1ヶ月が付く
```

237室ぶん・2,306掲載を実際に読んだ結果、**1部屋あたり平均11.4掲載**あり、
初期費用は掲載によって最大で **27万円** 違った（同じ部屋・同じ家賃）。
watch.py は1部屋につき1掲載しか見ないので、**高い方の掲載の数字で弾いていた**。

同時に、定数で置いている費目が実額と合わない:

| 費目 | watch.py の前提 | 実測で出てきた値 |
|---|---|---|
| 仲介手数料 | 0.55ヶ月 固定 | **不要（0円）** / 0.55 / **1.1ヶ月** |
| 保証会社 | 賃料の50% | 総賃料の30% / 40% / 80% / **100%** |
| 諸費用 | 4万 固定 | 2.2万 / 4.18万 / 4.4万 / 6.05万（内訳まで掲載にある） |

いずれも物件概要表に書いてある。読めば済む。

### 詳細ページを読むときの落とし穴（実測で全部踏んだ）

- **店の宣伝文を条件と読み違える。**「仲介手数料0円物件**多数**」「フリーレント」の語は
  取扱店舗のアピール欄に頻出する。**概要表の欄と取引態様以外は信用しない。**
- **月次の料率を初回保証料と取り違える。**「月次保証料：賃料等の1％」を拾うと 1,770円 になる。
  「月額賃料等の１００％（初回保証料）」のように**料率が先でラベルが後ろ**の書き方もある。
- **`B1-1階`（地下1階〜1階のメゾネット）を階数として読めない。** 地下住戸を通してしまう。
- **フリーレントに条件が付く。**「フリーレント1ヶ月 **2月契約が条件**」＝入居時期次第で効かない。
- **ＦＲ と略される。**「ＦＲ期間での賃料免除相当額」は フリーレント の言い換え。

## 家賃の上限 — **管理費・共益費込み**（2026-07-29 本人確定 / 2026-08-01 に19万へ）

`RENT_CAP_INCLUSIVE = True`。**賃料 + 管理費・共益費 の合計が19万円以下**のものだけを通す。
18万→19万で候補の母数は 140室 → 237室（実測）。

### 18万に上げても、初期費用40万の方が先に効く

敷礼ゼロ・仲介0.55ヶ月・保証50%・諸費用4万で計算すると:

```
込18.0万 / 管理費     0円 → 初期費用 409,000円  NG
込18.0万 / 管理費 5,000円 → 初期費用 403,750円  NG
込18.0万 / 管理費 8,000円 → 初期費用 400,600円  NG
込18.0万 / 管理費10,000円 → 初期費用 398,500円  OK
込18.0万 / 管理費15,000円 → 初期費用 393,250円  OK
```

管理費が賃料から差し引かれる分だけ仲介・保証料が下がるため、
**込18万ちょうどの物件は管理費が9千円以上ないと初期費用40万に収まらない**。
家賃上限を1万上げても、初期費用を据え置く限り実際に開く枠は限定的。

各サイトへのクエリは賃料（管理費抜き）で上限を投げている。
管理費は必ず0以上なので「賃料 ≤ 上限」は「込み ≤ 上限」の上位集合になり、**取りこぼしは出ない**。
込みで超過するものは取得後にこちら側で落とす。

## 初期費用40万の帰結 — 敷礼ゼロが事実上の必須条件

仲介0.55ヶ月・保証会社50%・諸費用4万で上限40万を解くと:

```
敷礼ゼロ       → 賃料 17.5万まで可
敷礼 計0.5ヶ月 → 賃料 14.1万まで
敷礼 計1ヶ月   → 賃料 11.8万まで   ← 想定レンジの外
```

**敷礼がほぼゼロでないと数学的に届かない。**

当初は SUUMO 側で `co=3`（礼金なし）を掛けて母数を落としていたが、
「敷金ゼロ＋礼金0.5ヶ月」は賃料14.1万まで通るため取りこぼす。撤去して全件走査に変えた。
実測では 85件中77件が初期費用で落ちる。ここが最も強い足切りになっている。

### LIFULL HOME'S を「未対応」としていたのは誤りだった（2026-07-31 訂正）

以前「ページは200で返るが物件データがサーバ側で描画されない」と記録していたが、
これは**駅スラッグを取り違えて404ページを掴んでいた**ための誤判定。
404ページはナビゲーションだけを含むので、`万円`の出現がナビ由来しか無く、
「物件が描画されていない」ように見えていた。
正しいスラッグ（例 `oimachi_00603`）ならHTMLに物件が全部入っている。

### HOME'S の実測パラメータ

- 駅URL: `https://www.homes.co.jp/chintai/tokyo/{slug}_{駅コード}-st/list/`
  スラッグは路線ページ（例 `/chintai/tokyo/yamanote-line/`）の
  `name="cond[roseneki][...]"` の隣の駅リンクから採れる
- `cond[monthmoneyroomh]`（**万円単位**。RENT_CAP//10000 を入れる）/ `cond[housearea]={AREA_QUERY_MIN}`
  / `cond[houseageh]=25` / `cond[walkminutesh]=15`
- `cond[housekouzougroup][rebar]=rebar` … 鉄筋系（RC/SRC）。**構造がサーバ側で効く唯一のサイト**
- `cond[mcf][220301]` バス・トイレ別 / `cond[mcf][223101]` 洗面所独立
  （実測：洗面所独立を外しても結果はほぼ変わらない＝絞りすぎではない）
- `cond[madori][15|22|23|25|32|33|35|42|43|45-]` … 1LDK以上
- ページングは `page=N`、**1ページ10件**。総件数は「総物件数：N件」から採る
- 0件の目印は `条件に一致する情報は見つかりませんでした`。
  **この目印が無いのに物件ブロックも無い場合はレート制限**なので、
  待って引き直す（0件として扱うと静かに監視が死ぬ）

## いい部屋ネット（大東建託パートナーズ）について

詳細条件が**URLに乗らない**。`detail.priceMax=...` 等を付けても
`serializedCondition` は全項目 null のまま返る（条件はクライアント側が保持している）。
一方で**物件データは `__NEXT_DATA__` の `buildingSearchResult.buildings` に全部入っている**ので、
区単位で全ページ取ってこちらで絞る形にするしかない。

**403はレート制限ではない。**当初「待てば戻る」と判断して90秒×3回の待ちを積んだが、
これは誤診だった。同じヘッダを送っても **curl は200、urllib は403** になる。
TLS/HTTPのクライアント指紋で弾いているので、待っても永久に通らない。
取得するなら curl をサブプロセスで呼ぶこと。

### at home の駅スラッグ

`tamachi` / `takanawagateway` / `shinagawa` / `osaki` / `gotanda` / `meguro` / `oimachi` / `omori`
（`https://www.athome.co.jp/chintai/tokyo/{slug}-st/list/`。`ohmori` は404）

## 自動判定できないもの（通知後に人が見る）

1. **各室の畳数**（リビング6畳・寝室4畳以上）— 両サイトにフィルタが無い
2. **二人入居可** — 不動産ジャパンは `rsdn[]=RSDN06` で絞れるが、
   付けると母数が激減するため取得段階では外し、詳細ページの記載を通知に載せる
3. ハトマーク側の構造（RC/SRC）— `mansion` 種別での近似
