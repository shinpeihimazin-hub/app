# 会社Claude Code最適化 — 引き渡しキット

外部接続不可・未承認プラグイン導入不可の会社環境で動く Claude Code に対して、
**品質を上げつつトークン効率を良くする仕組みを、会社のClaude自身に作らせる**ための
コピペ用プロンプト集。

設計の根拠・ROI試算・失敗モードは
[`../docs/superpowers/specs/2026-08-05-company-claude-handoff-design.md`](../docs/superpowers/specs/2026-08-05-company-claude-handoff-design.md) にある。

---

## 使い方

各ファイルの中の **コードブロックだけをコピー**して、会社のClaude Codeに貼る。
コードブロックの外にある解説は、あなた（人間）向けであって、貼る必要はない。

**毎回、新しいセッションで貼ること。** 前のフェーズの文脈を引きずると、
そこで読んだ大量のファイルに最後まで課金され続ける。
引き継ぎは `docs/ai-context/repo-map.md` 経由で行われるので、会話を続ける必要はない。

| 順 | ファイル | 会社Claudeがやること | あなたのゲート |
|---|---|---|---|
| 1 | [`step0-baseline.md`](./step0-baseline.md) | 過去ログから**改善前の数字**を集計 | ユーザー発言数の中央値を覚えておく |
| 2 | [`phase0-survey.md`](./phase0-survey.md) | リポジトリを調査し `repo-map.md` を書く | **地図の精度。ここが雑なら以降は全部無駄** |
| 3 | [`phase1-claude-md.md`](./phase1-claude-md.md) | `CLAUDE.md` を書く（100行以内） | 行数と、規律7条が骨抜きになっていないか |
| 4 | [`phase2-subagents.md`](./phase2-subagents.md) | サブエージェント2体を書く | explorer に書き込み権限が無いか |
| 5 | [`phase3-hooks.md`](./phase3-hooks.md) | フック（無効設置）＋承認資料 | `settings.json` を編集していないか |

所要は合計2〜3時間（ゲート確認込み）。1〜5を一気にやる必要はない。
**1と2だけ済ませて数日使ってみる**のでもいい。

## 会社側に生まれるもの

```
docs/ai-context/measure.py          … 測定スクリプト（ローカル集計のみ）
docs/ai-context/baseline-<日付>.md  … 改善前の数字
docs/ai-context/repo-map.md         … 地図（詳細の恒久的な置き場）
CLAUDE.md                           … 地図・コマンド・規約・規律（100行以内）
.claude/agents/explorer.md          … 読解役
.claude/agents/reviewer.md          … レビュー役
.claude/hooks/scope-guard.sh        … フック本体（未登録＝無効）
docs/hook-review.md                 … 社内確認用の説明資料
```

**すべて、その場で書かれるテキストファイル。ダウンロードは一切発生しない。**

## 途中で止めていい場所

| ここまで | 効果 | 社内リスク |
|---|---|---|
| step0 のみ | 現状把握だけ。数字が出る | ほぼ無し（ローカルの読み取りと集計） |
| phase1 まで | **効果の大半はここで出る。** 探索とコマンド試行錯誤が消える | 低（ファイルを1つ置くだけ） |
| phase2 まで | トークン効率の本命。読解・レビューの文脈汚染が消える | 低（ファイルを置くだけ） |
| phase3 | 規律を機構で担保。上乗せ分 | **要承認**（コマンドの自動実行） |

**phase3 が通らなくても、1と2で成立する設計にしてある。**
Cは上乗せであって前提ではない。

## 効果の確認

phase1・phase2 を入れて1〜2週間運用したら、`measure.py` を再実行して
`baseline-<日付>.md` と比べる。

見るのは **1セッションあたりのユーザー発言数の中央値**。
これが往復回数そのもの。

### 期待値と、その限界

設計時の見込みは**往復20〜40%減、トークン25〜45%減**。ただしこれは推測であり、
実測値ではない。

そして測定自体に限界がある。**タスクの難易度がばらつくので、大きな差しか検出できない。**
5%の改善は雑音に埋もれる。逆に30%動いたなら本物。
あなた自身が慣れて上手くなる効果も混ざる。この精度のものだと理解した上で使うこと。

## 未確認事項

**`.claude/` 配下のファイル設置が、社内ルール上「プラグイン導入」に当たるかは未確認。**

マーケットプレイスのプラグインは外部からコードを取得するが、
`CLAUDE.md` / `.claude/agents/` はgitにコミットするただのテキストで、
Claude Code本体が読むだけ。外部通信は発生しない。**経路が違う。**

ただし社内ルールがこの区別をしている保証は無い。気になるなら、
phase2 に進む前に「AIへの指示を書いたテキストファイルをリポジトリに置く」形で
確認を取っておくとよい。phase1（CLAUDE.md 1ファイル）までなら、
通常のドキュメント追加と区別がつかないので、まず問題にならない。
