# absorb — 部品を食って装備に変える

対象: $ARGUMENTS

「調べた」で終わらせない。**台帳に記録され、可能なら導入・検証されて初めて「食った」**とする。

## 鉄の掟
```
検証の出力を添えずに ✅導入済 と書かない。
一次ソース（公式リポジトリ/ドキュメント）を見ずに台帳へ書かない。
```
| 言い訳 | 現実 |
|---|---|
| 「起動確認したから✅でいい」 | 起動≠実利用可。制約があれば⚠️と理由を書く |
| 「記事に119件とあったから119件」 | 二次情報は古い。一次ソース（marketplace.json等）で数える |
| 「有名なツールだから信頼確認は省略」 | 提供元・ライセンス・データの行き先の確認は省略不可 |

## 現在の台帳と装備
- 台帳: @ai-agent-builder/19-living-registry.md の状態を確認してから始める（既に食っていれば再検証・更新に切り替える）
- MCP設定: !`cat .mcp.json 2>/dev/null || echo "(なし)"`
- 外部疎通: !`code=$(curl -m 4 -sS -o /dev/null -w "%{http_code}" https://example.com 2>/dev/null); [ "$code" = "200" ] && echo "OK" || echo "遮断あり——キー不要MCPでも外部APIに依存するものは動かない可能性。導入検証は起動確認まで"`

## 手順（1件ずつ。spike-first・fail-fast）

### 1. 分類
対象が何かを判定: MCPサーバー / REST API / スキル / サブエージェント / フレームワーク・SDK / ランタイム。複数該当（例: SDKとMCPの両提供）なら分けて扱う。

### 2. 調査（メイン文脈を守る）
`agent-builder-researcher` サブエージェントに委譲し、次だけを要約で受け取る:
- 何ができるか（1-2行）／提供元と信頼性（公式か・メンテ頻度）
- 導入方法（正確なコマンド・設定JSON）／APIキー等の前提
- 既存装備との重複（台帳に類似があるなら食う価値の判定）
軽い対象（1ツールの仕様確認程度）ならWebSearchで直接調べてよい。**WebFetchは許可ドメイン外で失敗しやすいのでWebSearch優先。**

### 3. 導入判定
- **キー不要＆この環境で動く** → 即導入する。MCPなら `.mcp.json` に追記、スキル/サブエージェントなら `.claude/` に配置
- **キーや人間側アクションが必要** → `ai-agent-builder/templates/mcp-optional.json` に「差せば動く形」で追記（取得先URL付き）
- **今は不要（カタログ価値のみ）** → 台帳に📖調査済として記録するだけ

### 4. 検証（導入した場合のみ・代表1件）
- MCP: サーバーの起動確認（`npx -y <pkg> --version` 等）。ネットワーク遮断環境では外部API依存のものは「起動確認まで」と明記
- スキル/サブエージェント: frontmatterの妥当性と、可能なら最小の実呼び出し1回
- 失敗したらリトライ1回まで。ダメなら状態⚠️で理由を台帳に書く（無かったことにしない）

### 5. 台帳追記（必須）
`ai-agent-builder/19-living-registry.md` の該当カテゴリ表に1行追加（名前/状態/何ができるか/導入方法/キー/検証日/出典）。既存エントリなら検証日と状態を更新。関連があれば [`18`](../../ai-agent-builder/18-third-party-ecosystem.md) のカテゴリ表・READMEの装備表にも反映。

### 6. コミット
`git add` → `feat(registry): absorb <名前>` でコミット。プッシュはユーザーの運用に従う。

## sweep モード（$ARGUMENTS が "sweep" のとき）
新着を巡回して食い候補を挙げる:
1. WebSearchで探索: 「new MCP servers <今月>」「awesome-claude-code updates」「Anthropic directory new」「agent framework release <今年>」等
2. 台帳に無いもののうち、**汎用性が高い順に上位5件**を候補として提示（各1行: 何ができるか＋食う価値）
3. ユーザーが選んだものを上の手順1-6で1件ずつ食う（勝手に大量導入しない）

## 制約
- 1回の起動で食うのは最大3件まで（ツール数を一気に増やすと選択精度が落ちる: 18 §6）
- サードパーティは信頼性確認（提供元・データの行き先・最小権限: 08 §6.5）を省かない
- 検証していないものを✅にしない。事実と推測を混ぜない
