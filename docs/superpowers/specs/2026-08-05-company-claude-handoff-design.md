# 会社Claude Code最適化 — 段階プロンプト指示書 設計

作成日: 2026-08-05

## 目的

会社（外部接続不可・未承認プラグイン導入不可）のClaude Code環境に対して、
**このリポジトリを一切参照させずに**、品質向上とトークン効率化の仕組みを構築させる。

本設計の成果物は仕組みそのものではなく、**仕組みを作らせるためのコピペ可能な指示書**である。

## 確定した前提

| 項目 | 内容 |
|---|---|
| ツール | Claude Code（社内ゲートウェイ経由。APIキーは手元に無い） |
| ネットワーク | 外部接続不可。ダウンロードを伴う導入は一切できない |
| 制約 | **未承認プラグイン導入＝インシデント** |
| 対象範囲 | まず本人ひとり |
| 主戦場 | 実装 / 既存コード・仕様の読解 / レビュー・不具合調査 |
| 痛み | 無駄な往復（再説明・見当違い）と、コスト |
| 利用量 | ほぼ終日（6時間以上） |
| 受け渡し | 個人環境から会社PCへコピペ可能 |
| **未確認** | `.claude/` 配下のファイルが社内ルール上「プラグイン導入」に当たるか |

### プラグイン導入とファイル設置の区別

マーケットプレイスのプラグインは外部からコードを取得する。
CLAUDE.md・`.claude/agents/`・`.claude/hooks/` は、利用者がgitにコミットするただのテキストであり、
Claude Code本体が読むだけで外部通信は発生しない。**経路が違う。**

ただし社内ルールがこの区別をしている保証はないため、本設計は
「区別が無くても段階1まではほぼ確実に安全」な順序で積む。

## 採用した構成

### 内容軸: A→B→C の3段
- **A. 地図と規律** — CLAUDE.md 1ファイル。探索の消滅と規律の明文化
- **B. サブエージェント分離** — 読解・レビューを別コンテキストへ退避（トークン効率の本命）
- **C. フック強制** — 頼まれていない変更を物理ブロック。**承認が要る前提で無効設置**

### 形式軸: 段階プロンプト（コピペ4枚＋測定1枚）

一撃プロンプトは、会社のコードベースを知らないまま大量生成し、
その手直しで往復が増える。目的（往復削減）と逆走するため不採用。

自己増殖型（メタ指示書）は、初回失敗時に破損箇所を追えないため不採用。


会社側に生まれるもの:
`docs/ai-context/repo-map.md` / `CLAUDE.md` / `.claude/agents/*.md` /
`.claude/hooks/scope-guard.sh`（無効）/ `docs/hook-review.md`

## 設計上の要

### 1. Phase 0 は `repo-map.md` 以外に書かせない

調査と生成を同一ターンでやらせると、調査が浅いまま生成に走る。分離が品質の担保。

出力先を画面ではなくファイルにする理由は2つ。
- 報告全文を手でPhase 1へ運ぶ作業が消える
- **各Phaseをまっさらなセッションで開始できる**。調査で読んだ大量の文脈に
  最後まで課金され続ける事態を避けられる（コストの痛みへの直撃）

副次的に `repo-map.md` は、CLAUDE.mdの行数制限で逃がした詳細の恒久的な置き場になる。

### 2. CLAUDE.md は100行以内

CLAUDE.mdは毎ターン読み込まれる。**長さがそのまま常時コストになる。**
地図と規律だけを置き、超過分は `repo-map.md` 側へ逃がして参照のみ残す。

構成は4ブロック（地図／コマンド／規約／規律）。
うち規律ブロックが往復削減の本命であり、中核は
**「着手前に、触るファイルを宣言させる」**——的外れを書き始める前に潰せる。

### 3. サブエージェントは2体のみ

- **explorer**（読解役）: Read/Grep/Glob のみ。`file:line` と短い結論を返す
- **reviewer**（レビュー役）: 差分の指摘のみ。書き込み権限なし

explorer には決定的な制約を1行入れる——**「原文を大量に引用して返すな」**。
これが無いと読んだ全文がメインに戻り、分離した意味が消える。
サブエージェント運用で最も頻出する失敗モード。

不具合調査は主戦場だが、3体目（bug-hunter）は作らない。
エージェントを増やすと「どれを呼ぶか」の判断が曖昧になり往復が増える。
explorerで足りない場面が実際に出てから追加する。

### 4. Phase 3 はフックと同時に「承認材料」を作る

未承認の自動実行は入れられない。スクリプトは `.claude/hooks/` に置くが
`settings.json` には登録しない（＝無効設置）。

`docs/hook-review.md` に、実行コマンド全文の逐条説明・
外部通信をしない根拠・失敗時の挙動・**1行での停止方法**を書かせる。
「AIが勝手にコマンドを実行する」と受け取られると話が止まるため、
止め方が明示されていることが承認通過に効く。

## 測定

Claude Code は会話ログを `~/.claude/projects/<project>/*.jsonl` に自動保存する。
**測定データはすでに貯まっている**ため、baselineを遡って取得でき、待ち時間が要らない。

| 指標 | 取り方 |
|---|---|
| セッションあたりユーザー発言数 | `role: user` の件数（＝往復回数） |
| セッションあたり累計トークン | `usage` フィールドの合計 |
| セッション所要時間 | 最初と最後のtimestamp差 |

集計はローカルのJSONLを読むだけで、送信は一切しない。

**未確認**: 社内ゲートウェイ経由では `usage` が入らない可能性がある。
Phase 0 の調査項目7で確認し、無ければトークン指標を落として往復回数と時間で見る。

### 測定の限界

タスク難易度がばらつくため厳密な比較にならない。**大きな差しか検出できない。**
5%の改善は雑音に埋もれる。30%動いたなら本物。本人の習熟効果も混ざる。

## ROI試算（推測。実測値はゼロ）

| 施策 | 消える往復 | 見込み | 確度 |
|---|---|---|---|
| コマンド事実の明記 | test/lint/buildの試行錯誤 | 1〜3往復/セッション | 高 |
| 地図（repo-map＋CLAUDE.md） | 初動の手探り探索 | 1〜2往復＋入力トークン大 | 高 |
| 着手前のファイル宣言 | 的外れ実装の手戻り | 手戻り1回＝数往復 | 中 |
| explorer分離 | 読解の文脈汚染 | セッション後半ほど累積 | 中〜高 |
| 要約再掲の禁止 | 出力トークン | 5〜15% | 中 |
| reviewer / scope-guard | （品質・レビュー負荷側） | — | 中 |

**合算見込み: 往復 20〜40%減、トークン 25〜45%減。**

時間換算（仮定を明示する）:
- 1日6時間のうち無駄な往復に溶けている割合を**仮に2割**とする
  ← **これが最も弱い前提。未測定**
- 1.2時間/日 が無駄 → その3〜5割が消えるなら **0.4〜0.6時間/日**
- 月20営業日で **8〜12時間/月**

導入コストは4フェーズ＋ゲート確認で合計2〜3時間。
見込みが当たれば1週間以内に回収する。外れても損失は3時間。

**この試算の弱点は step0-baseline.md の実行で潰せる。** だから測定を先頭に置く。

## 想定される失敗モード

1. **CLAUDE.mdが守られない** — モデルは指示を無視することがある。
   だからCのフックが要る。物理的に止める層がないと規律は劣化する
2. **repo-map.md の陳腐化** — コード変更で自動更新はされない。
   CLAUDE.mdに「地図と実態がずれていたら指摘して止まれ」を入れ、腐敗を検知させる
3. **サブエージェントが呼ばれない** — 起動精度は description の質で決まる。
   「いつ使うか」を具体的な場面で書かせる
