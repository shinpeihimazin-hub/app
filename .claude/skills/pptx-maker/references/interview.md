# S1 インタビューガイド

目的：**「誰に・何を伝えて・どう動いてもらう資料か」**を一意に確定する。ここが曖昧なまま進むと後段全部が無駄になる。

## 確定必須の8項目（AskUserQuestionで。既に会話で判明している項目は聞かない）

| # | 項目 | 確定の基準 |
|---|---|---|
| 1 | 目的 | この資料で聴衆に取ってほしい行動が一文で言える（承認する/予算をつける/合意する…） |
| 2 | 聴衆 | 役職・前提知識・関心事。決裁者が誰かを分離して特定する |
| 3 | 結論 | **一文**。「要するに何が言いたいか」。これが言えないうちは次へ進まない |
| 4 | 主張の柱 | 結論を支える論点2〜4個 |
| 5 | 材料 | 手元にあるデータ・過去資料・実績（ファイルパス or 「無い」）。無いものは「要確認」扱い |
| 6 | 分量・時間 | 枚数目安と発表時間（例: 10枚/15分）。付録の要否 |
| 7 | トーン | 攻め（提案・売り込み）/守り（報告・説明）/中立（共有）。文体（です・ます/体言止め） |
| 8 | 制約 | 締切、社外秘レベル、入れてはいけない内容 |

## 進め方
- 1回のAskUserQuestionは最大4問。2回に分けてよい。
- 回答が矛盾したら（例: 聴衆は役員なのに詳細技術を全部入れたい）その場で指摘して解消する。
- 全項目確定したら `brief.md` に以下の形式で保存し、ユーザーに1画面で見せて確認：

```markdown
# ブリーフ: <資料名>
- 目的（期待する行動）:
- 聴衆 / 決裁者:
- 結論（一文）:
- 主張の柱: 1. / 2. / 3.
- 材料: （パス列挙。無いものは「要確認」）
- 分量: X枚 / Y分
- トーン:
- 制約:
```

## 停止条件
- 材料が「無い」だらけで結論の裏付けが立たない場合は、**作れる範囲（骨子だけ等）を提示して合意してから**進む。裏付けを捏造して埋めない。
