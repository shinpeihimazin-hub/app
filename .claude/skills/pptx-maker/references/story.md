# S3 ストーリー設計ガイド

目的：スライドの**並び＝論理の流れ**を承認ゲート①で固める。1スライド＝1メッセージ。

## 型の選択（ブリーフのトーンで決める）

| 型 | 並び | 向き |
|---|---|---|
| 課題解決型 | 表紙→現状/課題→原因→解決策→効果/根拠→体制/計画→まとめ | 提案・売り込み（攻め） |
| 報告型（SDS） | 表紙→サマリー→詳細（実績/差異/要因）→今後→まとめ | 定例報告・実績共有（守り） |
| PREP型 | 表紙→結論→理由→事例/データ→結論再掲→次アクション | 意思決定を急ぐ役員向け・短時間 |

- 決裁者が多忙なら**冒頭2枚目に「結論＋お願い事項」**を必ず置く（どの型でも）。
- 枚数が要件を超えたら、本文を削らず**付録（Appendix）へ降格**して調整する。

## アウトラインの出力形式（この形でユーザーに提示→承認ゲート①）

```markdown
# アウトライン: <資料名>（全X枚）
| # | 種別 | 見出し（＝そのスライドの主張・一行） | 中身の予定 | 材料 |
|---|---|---|---|---|
| 1 | 表紙 | <タイトル> | 日付・宛先・部署 | — |
| 2 | 結論 | 例:「A案の採択を提案します（投資額X、回収Y年）」 | 結論＋お願い事項 | brief |
| 3 | 課題 | 例:「現行プロセスは月Z時間の手戻りを生んでいる」 | 現状データ | 要確認 |
| ... | | | | |
```

## ルール
- **見出しは体言止めの題名ではなく「主張の一文」**にする（「市場動向」ではなく「市場は年率8%で縮小している」）。読み手が見出しだけ追えば話が通る状態＝流れの品質。
- 材料列に「要確認」が残るスライドは、承認①の際にユーザーへ明示して扱いを決める（データ待ち/推定と明記/削除）。
- 承認①で構成が変わったら、変わった範囲だけ再提示する（全部作り直して見せ直さない）。
