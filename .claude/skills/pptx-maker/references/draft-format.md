# S4 スライド原稿ガイド（deck.json）

目的：承認済みアウトラインを、build_deck.py が読める `deck.json` に落とす。文章の質はここで決まる。

## deck.json スキーマ

```json
{
  "title": "資料名（ファイルのプロパティに入る）",
  "slides": [
    {
      "layout": "テンプレ地図(template-map.json)に実在するレイアウト名 or 番号",
      "title": "スライド見出し（アウトラインの主張一文）",
      "body": ["箇条書き1", "箇条書き2", ["インデントした子項目"]],
      "placeholders": { "10": "レイアウト固有の枠(idx指定)に入れる文字列" },
      "images": [
        { "placeholder": 2, "path": "figs/chart1.png" },
        { "path": "figs/logo.png", "left_in": 8.5, "top_in": 0.3, "width_in": 1.2 }
      ],
      "notes": "発表者ノート（話す内容の下書き）"
    }
  ]
}
```

- `layout` は **inspect_template.py の出力にある名前だけ**を使う。無い名前を発明しない。
- `body` は省略可（表紙など）。ネスト配列はインデントレベル+1。
- `images.placeholder` は画像プレースホルダのidx。座標指定（`left_in`等、インチ）と排他。

## 文章のルール（品質の実体）
1. **見出し＝主張の一文**（story.mdから変えない。変えるなら承認①に戻る）。
2. 本文は**1スライド最大3〜4項目、1項目40字以内**。それを超える説明は notes（発表者ノート）へ。
3. 動詞で終える・数値は単位と期間を必ず付ける（「20%削減」→「月次工数を20%削減（3→2.4人月）」）。
4. 裏付けの無い数値は書かない。どうしても必要なら「（要確認）」を文中に残す——**消してよいのはユーザーだけ**。
5. 同じ語尾・同じ構文を3回以上連続させない（単調さは読み手の離脱を生む）。

## 図表
- 図表が要るスライドは、**先に dataviz スキルを読み込み**、その指針（チャート選定・配色・ラベリング）に従って matplotlib 等で PNG に描き出す（推奨: 幅2000px以上、背景透過なし）。
- 表は画像化せず `body` の箇条書き＋notesで代替できないか先に検討（pptxネイティブの表はv1非対応）。

## 提示（承認ゲート②）
deck.json をそのまま見せず、**スライドごとに「見出し／本文／図表／ノート」を整形したMarkdown**で提示する。修正指示はdeck.jsonに反映して差分だけ再提示。
