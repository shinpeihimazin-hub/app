# quiz.json スキーマ（study-buddy.html が読む出題データ）

`study-memory/quiz.json`。**`study-memory/*.md` が正、これは派生物。** md を直したら再生成する。
GitHub Pages（`main` 配信）から同一オリジンで `fetch` されるので、APIキーもCORS設定も不要。

```json
{
  "generated": "2026-07-29",
  "items": [
    {
      "id": "20260728-deadlock-conditions",
      "topic": "テクノロジ/OS",
      "tripped_on": "「循環待ち」と「相互排除」の区別がつかない",
      "questions": [ { "fmt": "...", "...": "..." } ]
    }
  ]
}
```

`id` は md のファイル名stem と**必ず一致させる**。貼り戻された結果を md に反映する時の鍵になる。

## 形式ごとの必須キー

### `mcq` — 4択
```json
{ "fmt":"mcq",
  "q":"デッドロックの発生条件のうち、複数のプロセスが資源を輪の形で待ち合っている状態はどれか。",
  "choices":["相互排除","循環待ち","専有と待機","非プリエンプション"],
  "answer":1,
  "why":"輪＝循環待ち。相互排除は「1つの資源を同時に使えない」ことで、待ちの形の話ではない。" }
```
`answer` は `choices` の**0始まりindex**。誤答選択肢は `tripped_on` から作る（`question-formats.md`）。

### `cloze` — 穴埋め・一問一答
```json
{ "fmt":"cloze",
  "q":"資源を持ったまま別の資源を待つ状態を何という？",
  "answer":"専有と待機",
  "accept":["hold and wait","ホールドアンドウェイト","保持と待機"],
  "why":"..." }
```
HTML側の照合は「NFKC正規化 → 空白除去 → 小文字化 → カタカナ→ひらがな」後の完全一致。
**表記ゆれは `accept` に列挙して吸収する。** 揺れが多い問いは cloze にしない（explainにする）。

### `calc` — 数値を変えた計算
```json
{ "fmt":"calc",
  "q":"稼働率 {a} の装置を {n} 台 並列に接続したときのシステム全体の稼働率は？",
  "vars":{ "a":{"values":[0.8,0.85,0.9,0.95]}, "n":{"values":[2,3]} },
  "expr":"1-Math.pow(1-a,n)",
  "round":4,
  "unit":"",
  "why":"並列＝両方 同時に落ちた時だけ停止。1-(1-a)^n。" }
```
- `q` の `{変数名}` が `vars` の値で置換される
- `vars` は `{"values":[...]}`（列挙）または `{"min":,"max":,"step":}`（等差）
- `expr` は変数名だけをスコープに持つJS式。HTML側で毎回 計算するので、**事前生成した問題の使い回しにならない**（毎回 数値が変わる）
- `round` は小数点以下の桁数。割り切れない値が混ざる `values` を選ばない（採点で揉める）
- `expr` は `new Function` で評価される。**この JSON は自分がリポにコミットしたものだけを置く。**外から受け取った quiz.json を読み込ませない

### `explain` — 口頭試問（HTMLでは採点しない）
```json
{ "fmt":"explain",
  "q":"デッドロックが起きる条件を、自分の言葉で説明して。",
  "must":["相互排除","専有と待機","非プリエンプション","循環待ち","4つ全部 揃って初めて起きる"] }
```
- `must` = 必須要素リスト。**聞く前に確定させる**（後付け判定はブレる）
- HTMLは回答を集めて `[EXPLAIN]` としてエクスポートするだけ。**◯×を付けない**（自然文の採点はLLMが要る）
- HTML側は `must` を「自己照合」トグルで見せるが、それは記録に残さない

## 1項目に何形式 入れるか

その項目に**向く形式だけ**入れる（`question-formats.md` の適性表）。向かない形式を埋めるために質の低い問題を作らない。1形式しか入らない項目があってもよい。

## 再生成の手順

```bash
# 対象の md を確認
grep -H -E "^(id|topic|tripped_on):" study-memory/*.md
```
md を読んで各項目の `questions` を作り、`quiz.json` をWriteで丸ごと書き直す。
差分が出たら **commit して push する**（Pages＝`main` 配信なので、`main` に入るまでスマホには降りない）。
