# 出題形式リファレンス

形式は4つ。**毎回 違う形式で出す**のが目的（同じ形式の反復は「その問題文への暗記」に退化する）。

## 形式の選び方

### ステップ1: その項目に向く形式を絞る

| 項目の性質 | 向く形式 | 向かない形式 |
|---|---|---|
| 手順・数値計算がある（稼働率、基数変換、CPI、ページング） | `calc` | `cloze`（暗記で解けてしまう） |
| 条件・要素の列挙（デッドロックの4条件、ACID、OSI7層） | `explain` `cloze` | — |
| 紛らわしい用語のペア（スループット/レスポンスタイム、リスク移転/回避） | `mcq` `explain` | `calc` |
| 定義そのもの（用語→意味） | `cloze` | `calc` |
| 図・構造の理解（正規化、木構造、サブネット） | `explain` `calc` | `cloze` |

`calc` が成立しない項目（数値が絡まない）に無理やり計算問題を作らない。

### ステップ2: 前回と違う形式を選ぶ
- `formats_used` の**末尾**と同じ形式は選ばない。
- ステップ1で残った形式が1つしかないなら、それを使ってよい（ただし問題文の切り口を変える）。
- 残り候補が複数あるときは `shuf -n 1` で選ぶ。自分の「なんとなく」で選ばない（4択に偏る）。

## mcq — 4択（本番と同じ形）

**測るもの**: 紛らわしいものを識別できるか。本番の形式への慣れ。

**作り方**
1. 正解を1つ決める。
2. **誤答選択肢は `tripped_on` から作る。** 本人が実際に取り違えたものを選択肢に入れる。ここが全て。
3. 残りは「同じ分野の実在する用語・値」で埋める。存在しない造語を混ぜない。
4. 選択肢の長さを揃える。正解だけ長いと形で当てられる。

**良い例**（`tripped_on: 「循環待ち」と「相互排除」の区別がつかない`）
> デッドロックの発生条件のうち、「複数のプロセスが資源を輪の形で待ち合っている」状態を指すものはどれか。
> ア 相互排除　イ 循環待ち　ウ 専有と待機　エ 非プリエンプション

→ 4つとも実在の条件で、本人が混同しているものが選択肢に並んでいる。消去法が効かない。

**悪い例**
> ア 循環待ち　イ TCP　ウ 正規化　エ サブネットマスク

→ 分野がバラバラで、意味が分からなくても消去法で当たる。理解を測れていない。

**判定**: 記号が合っていれば○。ただし**なぜそれを選んだかを1回だけ聞く**。当てずっぽうの正解を○にすると記憶の状態が嘘になる。理由が言えなければ `x` を記録する。

## cloze — 穴埋め・一問一答

**測るもの**: 用語と意味が双方向で結びついているか。短く終わるので、低覚醒の朝でも成立する。

**作り方**
1. 方向を決める。**用語→意味** と **意味→用語** を交互に使う（`formats_used` に両方 `cloze` と記録されるので、直近の出題文を見て逆向きにする）。
2. 穴を開ける場所は「その項目の急所」。てにをはや自明な語を抜かない。
3. 1問で答えるのは1つ。複数の穴を並べない（どこで詰まったか分からなくなる）。

**良い例**
> 「デッドロックの4条件のうち、資源を持ったまま別の資源を待つ状態を＿＿＿という」
> 「ACIDの『I』は何の略で、何を保証する？」

**悪い例**
> 「デッドロックとは、複数の＿＿＿が互いの＿＿＿を待ち合って、どちらも＿＿＿できなくなる状態」

→ 穴が3つ。何が分かっていて何が分かっていないか判別不能。

**判定**: 表記ゆれ・カタカナ英語の差は○。意味が合っていれば用語が英語でも日本語でも○。

## calc — 数字を変えた計算問題

**測るもの**: 手順を再現できるか。暗記では絶対に解けない形式。

**作り方（この手順を飛ばすと嘘の正解で採点する）**
1. 論点は同じまま、数値だけを変える。桁を極端にしない（本番の桁感に寄せる）。
2. **出題する前に、自分で答えを計算して確定させる。暗算しない。** Bashで計算する:
   ```bash
   python3 -c "print(1 - (1-0.9)*(1-0.9))"   # 並列稼働率
   python3 -c "print(int('1011', 2))"         # 基数変換
   ```
3. 割り切れない数値になったら、数値を選び直す（採点で揉める）。
4. 答えと計算過程を**手元に置いてから**出題する。同じメッセージに答えを書かない。

**良い例**
> 稼働率0.9の装置を2台 並列に接続したときの、システム全体の稼働率は？（小数第3位まで）

**悪い例**
> 稼働率0.87の装置を3台 直列、さらに0.93を2台 並列に接続し…

→ 論点が3つ混ざり、どこで間違えたか分からない。1問1論点。

**判定**: 答えが合っていても**計算過程を1行 言わせる**。数字だけ合って手順が違うことがある。過程が違えば `x`。

## explain — 説明させる（口頭試問）

**測るもの**: 自分の言葉で再構成できるか。理解の穴が一番はっきり出る形式。

**作り方**
1. **先に「必須要素リスト」を手元で作る。** 何が言えていれば○かを、聞く前に確定させる。後付けで判定するとブレる。
   例（デッドロックの4条件）: 相互排除／専有と待機／非プリエンプション／循環待ち の4つ、かつ「全部 揃って初めて起きる」こと。
2. 質問は一言で投げる。「デッドロックが起きる条件を、自分の言葉で説明して」
3. 教科書の文言を求めない。本人の言葉でよい。

**判定**
- 必須要素と照合し、**抜けている要素だけ**を指摘する。合っている部分の褒め直しはいらない。
- 全部揃っていれば `o`。1つでも欠ければ `x`（ただし言うのは「◯◯が抜けてる」だけ）。
- 「うろ覚えだけど…」と前置きされても、中身が揃っていれば `o`。

**この形式で言ってはいけないこと**
- 「よく理解できてるね」→ 中身のない称賛。何が合っているか具体的に言うか、何も言わない。
- 「整理できたね、じゃあ次に進もう」→ 禁止の型。次の問題が要るか聞くだけにする。
