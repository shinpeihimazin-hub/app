# S1 ヒアリングの進行手順

`condition-taxonomy.md` の107項目を、**答えやすい順**かつ**後の質問が賢くなる順**で埋める。

## 進行の原則

1. **ラウンド制。** 1ラウンド＝AskUserQuestion で最大4問。107問を機械的に浴びせない。
2. **生活から入り、条件に落とす。** 「バス・トイレ別は必要ですか」と聞く前に「自炊しますか」「在宅勤務はありますか」を聞く。生活が分かれば、条件の重要度はこちらで下書きでき、ユーザーは確認するだけで済む。
3. **既出は聞き直さない。** 会話ですでに判明した項目は記録して飛ばす。聞き直しは信頼を削る。
4. **推測で埋めない。** ◎項目は必ず本人に聞く。○項目で仮定を置いた場合は**「〜と仮定しました」と明示**して確認を取る。黙って埋めるのは禁止。
5. **`未記入` を隠さない。** 答えを保留された項目は `unknown: true` のまま次へ進み、ラウンド7の前にまとめて回収する。「なんとなく埋まったことにする」が最大の事故原因。
6. **各ラウンド終了時に `conditions.yaml` へ即保存。** セッションが切れても再開できる状態を常に維持する。

## ラウンド構成

### ラウンド0: 骨格（5項目・自由記述中心）

選択肢を出す前に、まず状況を言葉で聞く。ここで得た文脈が以降すべての質問の精度を決める。

| 聞くこと | 埋まる項目 |
|---|---|
| なぜ引っ越すのか（更新／転職／同居／広さ／家賃） | 文脈。以降の重要度判定の背骨になる |
| 誰が住むか（人数・続柄） | `CTR_occupants` |
| いつ住みたいか、期限はあるか | `TIM_movein_ideal` `TIM_movein_deadline` |
| どこへ通うか（複数可） | `LOC_commute_dest` |
| 月にいくらまで出せるか | `BUD_rent_max`（※管理費込みかを必ず確認する） |

**「なぜ引っ越すのか」を必ず最初に聞く。** 「家賃を下げたい」と「広くしたい」では、以降の全項目の重み付けが逆になる。

### ラウンド1: 生活動線（LIF・10項目）

**このラウンドが最も投資対効果が高い。** ここが埋まると、EQP・ROM・BLDの重要度をこちらで下書きでき、ユーザーの回答負荷が大きく下がる。

在宅勤務／自炊頻度／洗濯スタイル／車・自転車／生活リズム／持ち込む家具／数年内の生活変化。

このラウンドの終わりに、**下書きした重要度を提示して確認を取る**:

> 「週3で在宅勤務とのことなので、以下を MUST の候補にしました。よろしいですか。
> ・独立した部屋がもう1つ（`ROM_rooms_separate`）
> ・光回線の個別契約が可能（`EQP_internet`）
> ・RC造以上の遮音性（`BLD_structure`）
> 逆に、通勤時間は60分まで緩められると判断しました。」

### ラウンド2: 予算の詳細（BUD・10項目）

月額は済んでいるので、初期費用・敷礼・更新料・年収を埋める。

- `BUD_initial_max` は「貯金額」ではなく「**引っ越しに出せる額**」として聞く（家具・家電・引越業者代を別途確保する必要がある）
- `BUD_income_annual` は審査基準の説明とセットで聞く。理由を言わずに年収を聞かない

### ラウンド3: 立地（LOC・17項目）

`LOC_commute_dest` は済んでいるので、時間・乗換・除外エリア・騒音・ハザード・徒歩圏施設を埋める。

- **`LOC_area_exclude`（除外エリア）を必ず聞く。** 「ここだけは嫌」は本人しか知らず、聞かないと必ず後から出てくる
- 徒歩圏施設は**施設ごとに許容分数**を取る（スーパー5分／病院15分など粒度が違う）
- ハザードは「気にしますか」ではなく「浸水想定区域は避けますか」と具体的に聞く

### ラウンド4: 部屋と建物（ROM・BLD・28項目）

ラウンド1の下書きを土台に、確認と補完を行う。

- `ROM_layout` は**単一値でなく許容範囲**で取る（1Kと1DKを分けると母数を無駄に失う）
- `ROM_area_min` を必ず取る。間取り表記より信頼できる
- `BLD_quake_std`（新耐震）は築年数と別に聞く

### ラウンド5: 設備（EQP・16項目）

チェックリスト形式でよいが、**以下の3つだけは単独で丁寧に聞く**（コスト影響が大きく、誤答が多い）。

- `EQP_gas_type` — プロパンの月額差を実額で示してから聞く
- `EQP_washer_indoor` — 屋外置きの実害（寿命・冬季凍結）を示してから聞く
- `EQP_aircon` — 「あるか」ではなく「**何台設置済みか**」。追加設置は1台10万前後＋大家の許可

### ラウンド6: 契約と時期（CTR・TIM・21項目）

**後から覆せない項目群。** 該当するのに聞き漏らすと契約直前で破談になる。

- `CTR_contract_type`（定期借家）は、意味を説明してから聞く。知らずに「可」と答えさせない
- `CTR_pet` は「**将来飼う可能性**」まで聞く
- `TIM_current_notice` は「契約書を確認してください」と依頼する。記憶で答えさせない

### ラウンド7: 優先度と交換レート（PRI・5項目）

**最重要かつ最も手を抜かれやすいラウンド。** ここを飛ばすとスコアリングが動かない。手順は `scoring.md` に従う。

## 追い質問の発火条件（一覧）

| 発火元 | 条件 | 追い質問 |
|---|---|---|
| `LIF_wfh` | 週1日以上 | `ROM_rooms_separate` `EQP_internet` `BLD_soundproof_priority` を引き上げ。同時に `LOC_commute_time_max` の**緩和余地**を提案 |
| `LOC_commute_freq` | 週2日以下 | 通勤時間の上限を緩められる旨を、具体的な家賃差とともに提示 |
| `BLD_soundproof_priority` | 高 | `BLD_structure` を RC/SRC の MUST に格上げするか確認。`ROM_floor`（最上階・角部屋）と `EQP_window_double` も引き上げ |
| `EQP_gas_type` | 「不問」と回答 | プロパンの月額差を実額で提示し、`BUD_rent_max` への実質上乗せを示してから再確認 |
| `BUD_initial_max` | 家賃×4.5 未満 | 敷礼ゼロ・フリーレントへの誘導を提案し、`BUD_deposit_ok` `BUD_keymoney_ok` の MUST 格上げを確認 |
| `CTR_contract_type` | 定期借家を許容 | 契約期間と再契約条項を「個別確認必須」としてマーク |
| `LIF_cooking` | 毎日 | `EQP_stove`（口数・設置済みか）と `EQP_kitchen_space` を引き上げ |
| `LIF_laundry` | 部屋干し | `EQP_bath_dryer` を引き上げ、`ROM_balcony` を下げる |
| `TIM_flexible` | 柔軟 | 閑散期（4〜8月・11〜12月）を狙う選択肢を、条件改善の見込みとともに提示 |
| `CTR_occupants` | 友人同士 | 「ルームシェア可」は「二人入居可」と別条件であり母数が激減する旨を明示 |
| MUST 数 | 8個超 | `PRI_top3` を根拠に降格を相談（`scoring.md` の手順） |

## やってはいけないこと

| 誘惑 | 現実 |
|---|---|
| 「だいたい埋まったので探し始めよう」 | ◎に `未記入` が1つでもあればS3は通らない。例外を作れるのはユーザーだけ |
| 「この人はたぶんこう考えるだろう」と推測で埋める | 推測は事実として記録され、後で誰も検証しない。`unknown: true` の方が100倍安全 |
| 「質問が多いと嫌がられるから省略する」 | 省略した項目は内見後か契約直前に必ず問題化する。省略ではなく**順序と下書き**で負荷を下げる |
| 107項目を1画面で一気に聞く | 回答の質が落ちる。ラウンド制を守る |
| 「不問」と答えられたら即座に次へ | 高コスト項目（ガス種別・定期借家・室内洗濯機置場）は、影響を示してから**再確認**する。「知らずに不問」と「知って不問」は別物 |
