# 賃貸条件タクソノミ（S1ヒアリングの網羅リスト）

S1はこのファイルの全項目を走査する。**「聞かなかった項目」は存在してはいけない。**
答えが「こだわらない」なら `不問` と記録する。`不問` と `未記入` は別物であり、`未記入` が1つでも残る限りS3の凍結ゲートは通らない。

## 記号

| 記号 | 意味 | 未記入のまま凍結できるか |
|---|---|---|
| ◎ | 必須。本人にしか決められない。推測で埋めてはいけない | 不可 |
| ○ | 推奨。既定の仮定を置いてよいが、**置いた仮定を明示**して確認を取る | 仮定を明示すれば可 |
| △ | 任意。該当する場合のみ聞く（発火条件つき） | 可 |

## conditions.yaml のキー命名

各項目の `ID` がそのまま YAML のキーになる。値は以下のいずれか。

```yaml
BUD_rent_max:
  value: 130000          # 実際の値。不問なら null
  unknown: false         # 未記入なら true（この状態が1つでもあると凍結不可）
  rank: MUST             # MUST / WANT / NICE / 不問
  weight: 0              # WANT のときのみ 1-10
  note: "管理費込みの上限"
```

## 1. BUD — 予算

初期費用は「家賃の4.5〜6ヶ月分」に膨らむのが実態で、家賃だけ決めて破綻する典型パターン。**月額と初期費用は別々に上限を取る。**

| ID | 項目 | 重要度 | 型・選択肢 | 何が変わるか / 追い質問 |
|---|---|---|---|---|
| `BUD_rent_max` | 月額上限（管理費・共益費込み） | ◎ | 円 | 検索の第一フィルタ。**必ず「込み」で取る**。家賃だけで答える人が多く、管理費5,000〜15,000円の差で予算が崩れる |
| `BUD_rent_ideal` | 月額の理想値 | ○ | 円 | 上限との差＝交換レートの原資。「この条件を満たすなら上限まで出す」の判断に使う |
| `BUD_initial_max` | 初期費用の上限（手持ちから出せる総額） | ◎ | 円 | 敷礼ゼロ物件に絞るか否かの分岐。**S2bで家賃×4.5〜6の概算と突き合わせる** |
| `BUD_deposit_ok` | 敷金の許容月数 | ○ | 0 / 1 / 2 / 不問 | 敷金ゼロ物件は退去時精算が高額化する傾向。トレードオフとして提示する |
| `BUD_keymoney_ok` | 礼金の許容月数 | ○ | 0 / 1 / 2 / 不問 | 礼金は返還されない純コスト。ゼロ限定にすると母数が大きく減る |
| `BUD_agent_fee_ok` | 仲介手数料の許容 | ○ | 0.5ヶ月 / 1ヶ月 / 不問 | 宅建業法の上限は家賃1ヶ月＋税。半額・無料を掲げる業者もある |
| `BUD_renewal_ok` | 更新料の許容 | ○ | なし / 1ヶ月 / 不問 | 2年ごとの継続コスト。**関東は1ヶ月が慣例、関西はない地域も多く、地域で前提が変わる** |
| `BUD_income_annual` | 世帯年収（審査用） | ◎ | 円 | 入居審査の一般基準は「年間家賃 ≦ 年収の1/3」。S2bで機械的に検算する |
| `BUD_utilities_cap` | 光熱費の許容感 | △ | 円/月 | `EQP_gas_type` がプロパンだと都市ガス比で月数千円上振れする。ガス種別の重要度を決める材料 |
| `BUD_payment_method` | 家賃の支払方法の希望 | △ | 口座振替 / クレカ / 不問 | クレカ払い可なら実質還元が効く。こだわりがある人だけ |

**発火条件**: `BUD_initial_max` が家賃×4.5を下回る → 敷礼ゼロ・フリーレント物件への誘導を提案し、`BUD_deposit_ok` / `BUD_keymoney_ok` を MUST に格上げするか確認する。

## 2. LOC — エリア・立地

「駅徒歩」で聞くと失敗する。本当に効くのは**目的地までのドアtoドア時間**。

| ID | 項目 | 重要度 | 型・選択肢 | 何が変わるか / 追い質問 |
|---|---|---|---|---|
| `LOC_commute_dest` | 通勤・通学先の住所（最寄駅まで） | ◎ | 駅名 or 住所 | すべての立地判断の原点。複数ある場合は全部取る（同居人の分も） |
| `LOC_commute_time_max` | ドアtoドアの許容時間 | ◎ | 分 | **「駅徒歩10分以内」ではなくこれで聞く**。徒歩15分でも急行停車駅なら総時間は短い |
| `LOC_transfer_max` | 許容乗換回数 | ◎ | 0 / 1 / 2 / 不問 | 総時間が同じでも乗換2回は体感が別物。時間と分けて取る |
| `LOC_commute_freq` | 出社頻度 | ◎ | 週N日 / フルリモート | 週1出社なら通勤条件を大きく緩められる。**緩められる余地の発見が目的** |
| `LOC_rush_direction` | 通勤方向が上り（混雑側）か | △ | 上り / 下り | 座れるかどうかは生活の質に直結。時間だけでは見えない |
| `LOC_area_include` | 希望エリア・沿線 | ○ | 自治体名／沿線名／駅名の列挙 | 未指定なら `LOC_commute_*` から逆算して提案する |
| `LOC_area_exclude` | 除外エリア | ◎ | 自治体名／駅名の列挙 | 「ここだけは嫌」は本人しか知らない。**聞かないと必ず後で出てくる** |
| `LOC_walk_max` | 駅徒歩の上限 | ○ | 分 | ドアtoドアの内数。バス便を許容するかもここで確認 |
| `LOC_bus_ok` | バス便を許容するか | ○ | 可 / 不可 | 家賃が大きく下がる代わりに終バス時刻の制約がつく |
| `LOC_slope` | 坂道の許容 | △ | 可 / 不可 | 自転車・ベビーカー・重い買い物で効く。地図では見えず、内見で気づいて振り出しに戻る典型 |
| `LOC_night_safety` | 夜道の明るさ・人通り | ○ | 重視 / 不問 | 帰宅が遅い人には MUST になりうる |
| `LOC_noise` | 騒音源の許容 | ○ | 線路沿い可否 / 幹線道路沿い可否 / 繁華街可否 | 家賃が安い物件の理由がこれであることが多い。**安い理由の説明変数** |
| `LOC_hazard_flood` | 洪水・内水氾濫の浸水想定 | ◎ | 許容深さ or 不可 | ハザードマップで機械的に判定可能。**聞かれないと誰も考えないが、後戻り不能な項目** |
| `LOC_hazard_landslide` | 土砂災害警戒区域 | ○ | 可 / 不可 | 同上 |
| `LOC_hazard_quake` | 揺れやすさ・液状化リスク | ○ | 重視 / 不問 | `BLD_structure` `BLD_quake_std` と組で評価する |
| `LOC_facility` | 徒歩圏に必要な施設 | ○ | スーパー／コンビニ／ドラッグストア／病院／保育園／小学校／ジム／銀行 の複数選択＋各許容徒歩分 | 生活の満足度を最も左右する。**施設ごとに許容分数を取る**（スーパー5分・病院15分など粒度が違う） |
| `LOC_school_district` | 学区の指定 | △ | 学校名 | 子どもがいる場合のみ発火。指定があれば実質最強のMUSTになる |

**発火条件**: `LOC_commute_freq` が週2日以下 → `LOC_commute_time_max` の緩和余地を明示的に提案する（「週1出社なら60分でも実質コストは低い」）。

## 3. BLD — 建物

| ID | 項目 | 重要度 | 型・選択肢 | 何が変わるか / 追い質問 |
|---|---|---|---|---|
| `BLD_structure` | 構造 | ◎ | 木造 / 軽量鉄骨 / 重量鉄骨 / RC / SRC / 不問 | **遮音性は SRC・RC > 重量鉄骨 > 軽量鉄骨 > 木造**。騒音のクレームの大半はここ。家賃にも直結 |
| `BLD_soundproof_priority` | 音への敏感さ | ◎ | 高 / 中 / 低 | `BLD_structure` を MUST にすべきかの判定材料。在宅勤務・楽器・小さい子どもがいると跳ね上がる |
| `BLD_age_max` | 築年数の上限 | ○ | 年 / 不問 | 家賃との交換レートが最も大きい項目のひとつ |
| `BLD_quake_std` | 新耐震基準を必須とするか | ◎ | 必須 / 不問 | **1981年6月1日以降の建築確認が新耐震**。築年数と混同されやすいので独立項目にする。旧耐震は住宅ローン・保険でも不利 |
| `BLD_type` | 建物種別 | ○ | マンション / アパート / 一戸建て / テラスハウス / 不問 | 「マンション」の語を木造アパートに使う募集もあるため、`BLD_structure` と必ず併記して確認する |
| `BLD_floors_total` | 建物の総階数 | △ | 階 | 3階建て以下だとエレベーターがない可能性が高い |
| `BLD_elevator` | エレベーター | ○ | 必須 / 不問 | `ROM_floor` が3階以上かつ必須なら強い制約になる |
| `BLD_autolock` | オートロック | ○ | 必須 / 不問 | 家賃の上振れ要因。防犯の優先度と併せて判断 |
| `BLD_delivery_box` | 宅配ボックス | ○ | 必須 / 不問 | 単身・共働きでは満足度が高い割に家賃影響が小さい。**費用対効果の良い条件** |
| `BLD_security` | その他の防犯設備 | △ | モニタ付インターホン／防犯カメラ／管理人常駐 の複数選択 | 女性の単身入居では MUST 化しやすい |
| `BLD_mgmt_type` | 管理形態 | △ | 常駐 / 日勤 / 巡回 / 自主管理 | 共用部の清潔さとトラブル対応速度に直結。長く住むなら効く |
| `BLD_units_total` | 総戸数 | △ | 戸 | 戸数が多いほど1戸あたりの管理費負担が下がる傾向 |
| `BLD_trash` | ゴミ出しのルール | ○ | 24時間可 / 収集日のみ | 生活の手間に効く割に、募集情報では見落とされやすい |
| `BLD_bike_parking` | 駐輪場 | ○ | 必須 / 不要 / 不問（＋台数） | 台数まで取る。1台のみで足りないケースが多い |
| `BLD_car_parking` | 駐車場 | ○ | 必須 / 不要（＋月額上限・車種） | 敷地内か近隣かで月額が数万変わる |

**発火条件**: `BLD_soundproof_priority` が「高」 → `BLD_structure` を RC/SRC の MUST に格上げするか確認し、同時に `ROM_floor`（最上階・角部屋）と `EQP_window_double` の重要度も引き上げる。

## 5. EQP — 設備

「あれば嬉しい」で流すと後悔する項目群。**光熱費と家事時間に効くものを先に聞く。**

| ID | 項目 | 重要度 | 型・選択肢 | 何が変わるか / 追い質問 |
|---|---|---|---|---|
| `EQP_gas_type` | ガス種別 | ◎ | 都市ガス / プロパン可 / 不問 | **プロパンは都市ガス比で月数千円高い＝実質家賃が上がる**。家賃の安さがこれで相殺される典型。必ず聞く |
| `EQP_bath_toilet_sep` | バス・トイレ別 | ◎ | 必須 / 不問 | 単身向けの最頻出MUST。ここを不問にできると母数と家賃が大きく改善する |
| `EQP_washstand` | 独立洗面台 | ○ | 必須 / 不問 | 朝の動線。同居人がいると効果が大きい |
| `EQP_reheat` | 追い焚き | ○ | 必須 / 不問 | 単身では過剰、複数人では実質必須に近い |
| `EQP_bath_dryer` | 浴室乾燥機 | ○ | 必須 / 不問 | 外干しできない立地・花粉症・共働きで価値が跳ねる |
| `EQP_washer_indoor` | 室内洗濯機置場 | ◎ | 必須 / 不問 | **屋外置きは洗濯機の寿命を縮め、冬に凍結する**。安い物件の理由がこれのことがある |
| `EQP_stove` | コンロ口数・種別 | ◎ | 1口 / 2口以上 / 3口 / IH希望 / ガス希望 | 自炊頻度で決まる。**設置済みか「コンロ置場のみ」かを必ず区別する**（後者は自費購入） |
| `EQP_kitchen_space` | 調理スペースの広さ | ○ | 重視 / 不問 | 自炊する人には間取り以上に効く。図面では分かりにくく内見必須項目 |
| `EQP_aircon` | エアコン | ◎ | 必要台数 | **設置済みの台数まで取る**。追加設置は1台10万前後＋大家の許可が要る |
| `EQP_internet` | インターネット | ◎ | 無料インターネット付 / 光回線導入済 / 各自契約可 / 不問 | 在宅勤務なら MUST。**「無料インターネット」は共有帯域で遅いことがあり、在宅勤務用途では光の個別契約可否の方が重要** |
| `EQP_window_double` | 二重サッシ・防音サッシ | △ | 希望 / 不問 | `LOC_noise` で線路・幹線道路を許容する場合の緩和策 |
| `EQP_amperage` | 電気容量（アンペア） | △ | A | 30A以下だと家電の同時使用でブレーカーが落ちる |
| `EQP_water_heater` | 給湯器の号数 | △ | 号 | 16号未満は複数箇所の同時使用が厳しい |
| `EQP_floor_heating` | 床暖房 | △ | 希望 / 不問 | 家賃上振れが大きい |
| `EQP_screen_door` | 網戸 | △ | 必須 / 不問 | 無い物件が実在する。通風を重視するなら確認 |
| `EQP_furnished` | 家具・家電付き | △ | 希望 / 不要 | 短期入居なら初期費用を大きく下げる |

**発火条件**: `EQP_gas_type` を「不問」と答えた場合 → プロパンの月額差を具体額で提示し、`BUD_rent_max` に実質いくら上乗せされるかを示してから再確認する。**「知らずに不問」と「知って不問」を区別する。**

## 6. CTR — 契約・入居条件

**ここは後から覆せない。** 該当するのに聞かれなかった場合、契約直前で破談になる。

| ID | 項目 | 重要度 | 型・選択肢 | 何が変わるか / 追い質問 |
|---|---|---|---|---|
| `CTR_contract_type` | 契約形態 | ◎ | 普通借家 / 定期借家も可 | **定期借家は期間満了で必ず退去**（再契約は貸主の任意）。家賃が相場より安い理由がこれのことが多く、見落とすと数年後に強制退去 |
| `CTR_occupants` | 入居人数と続柄 | ◎ | 人数＋続柄（単身／夫婦／同棲／友人／家族） | **「二人入居可」「ルームシェア可」は別条件**。友人同士は不可の物件が非常に多い |
| `CTR_pet` | ペット | ◎ | 不要 / 猫N匹 / 犬N匹（犬種・サイズ） / 将来飼う可能性あり | **「将来飼うかも」を必ず聞く**。後から不可物件では飼えない。ペット可は敷金が1ヶ月増えるのが通例 |
| `CTR_instrument` | 楽器 | ◎ | 不要 / 種類（電子/生） | 生ピアノ・管楽器は物件が激減する。電子楽器なら時間帯制限で足りることが多い |
| `CTR_smoking` | 喫煙 | ○ | 室内可が必要 / ベランダのみ / 不要 | 禁煙物件が増えている。原状回復費にも影響 |
| `CTR_soho` | 事務所・SOHO利用 | ◎ | 不要 / 法人登記が必要 / 作業のみ | **法人登記の可否は物件が大きく絞られる**。在宅勤務（作業のみ）とは別条件なので混同しない |
| `CTR_guarantor` | 連帯保証人 | ◎ | 立てられる / 立てられない | 立てられない場合は保証会社必須の物件に限定される。**審査の可否を左右する** |
| `CTR_guarantee_co` | 保証会社の利用 | ○ | 可 / 不可 | 初回に家賃の50〜100%、以後年1万円程度の更新料。初期費用の計算に必要 |
| `CTR_employment` | 就業形態 | ◎ | 正社員 / 契約 / 派遣 / 自営 / 経営者 / 学生 / 無職・転職中 | 審査の通りやすさを左右する。**自営・転職直後は書類が変わる**ので先に把握する |
| `CTR_nationality` | 国籍・在留資格の考慮 | △ | 該当あり / なし | 該当する場合、外国籍可の物件に絞る必要がある |
| `CTR_age_consider` | 高齢入居の考慮 | △ | 該当あり / なし | 該当する場合、対応物件に絞る |
| `CTR_stigmatized` | 心理的瑕疵（事故物件） | ◎ | 不可 / 条件次第で可 | 「条件次第で可」なら家賃を大きく下げられる。**本人に聞かずに除外も採用もしてはいけない** |
| `CTR_diy` | DIY・原状回復 | △ | 壁に穴を開けたい / 不問 | 該当者のみ |
| `CTR_current_status` | 物件の現況 | ○ | 空室のみ / 居住中も可 | 居住中は内見できず入居時期も読めない |

**発火条件**: `CTR_contract_type` で定期借家を許容 → 契約期間と再契約条項を必ず個別確認する項目としてマークする。

## 9. PRI — 優先度とトレードオフ

**このカテゴリが埋まらない限り S5 のスコアリングは動かない。** 1〜8の全項目を機械的にここへ流し込む。

| ID | 項目 | 重要度 | 型・選択肢 | 内容 |
|---|---|---|---|---|
| `PRI_rank` | 全項目の3分類 | ◎ | MUST / WANT / NICE / 不問 | **MUST＝1つでも欠けたら候補から除外**。WANT＝加点。NICE＝同点時の決め手 |
| `PRI_weight` | WANT項目の重み | ◎ | 各1〜10 | 相対値でよい。重み合計の正規化はスクリプトが行う |
| `PRI_exchange_rate` | 交換レート | ◎ | 「条件Xを満たすなら家賃+N円まで許容」 | **これが本命**。最低でも上位5つのWANTについて金額に換算する。金額に換算できない条件は実はMUSTかNICEのどちらかであり、その場合は分類をやり直す |
| `PRI_top3` | 絶対に譲れない上位3つ | ◎ | 項目IDを3つ | MUSTが多すぎるときの最終防衛ライン。**S2bで母数ゼロ警告が出たとき、これ以外のMUSTを降格する順序を決める** |
| `PRI_dealbreaker` | 一発除外の条件 | ◎ | 自由記述 | 分類に収まらない直感的な拒否条件（「この駅だけは無理」等）を取りこぼさないための受け皿 |

### MUSTの上限ルール

MUST が **8個を超えたら S2b が警告を出す**。母数がゼロに近づくため、`PRI_top3` を根拠に降格の相談を行う。ユーザーが「それでも全部MUSTだ」と明示した場合のみ、警告つきで凍結を許可する（判断はユーザーのもの）。

以下を全て満たさない限り S4 へ進めない。

- [ ] 上位5つのWANTに `PRI_exchange_rate` が付いている

- [ ] ユーザーが明示的に「凍結してよい」と述べた
